From key to sound

Until now, programs ran from top to bottom and stopped. An event lets the program wait for you, and react when you act.

the eventkeydowna key goes down
→
the browser callshandleKeyDown(event)the listener connects them
→
the dataevent.keynoteForKey(…)
→
the responsea sound

Functions, variables and conditionals from last week decide what the data sounds like.

Recap the morning through the instrument, in five minutes. Press a few keys on the pad and follow the strip: the event fires, the browser calls the handler with the event, event.key is the data, the lookup turns it into a note (the home row, like a piano), and the response is a sound. Keys that aren't notes stop at the data box. Then walk through the Canvas exercises page and the three tracks.
Introduction · Before you play

Two things that look like bugs

Click the page first
Only the part of the screen you last clicked hears the keys. If you clicked in the console, your key presses go there, and the page hears nothing.

After every save the page reloads: click it again.

Start the sound in the handler
Browsers only play sound after a key press or a click. A key press counts, so the first line inside your handler switches the sound on:
every handler today

    

  

  
The two issues TAs will see most, before anyone starts. Focus: keys typed while the console is focused never reach the page; click on the page body. Sound: Tone.start() at the top of the key handler; every starter file already has it. If a student hears nothing but the console logs keys, these two are the first things to check (then volume and headphones).

Name the handler

  

    

      

        
4aMove the function out of addEventListener and give it a name: function handleKeyDown(event) { … }. Then hand it over: document.addEventListener("keydown", handleKeyDown);

        
4bNow add brackets: handleKeyDown(). Save, read the console, and answer on the right.

        
4cWrite why in a comment, then take the brackets off again.

      

    

    

      
With the brackets

      

      

    

  

  
Done whenhandleKeyDown is handed over without brackets, your instrument plays as before, and your comment says what the brackets did.

  
The most common event bug, and last Tuesday's functions again: here the browser does the calling, not us. With brackets, handleKeyDown() runs once while the page loads. There's no event yet, so event is undefined and the console shows TypeError: Cannot read properties of undefined (reading 'key'). The script stops on that line, so addEventListener never gets a function. Same idea as the morning's "Hand over the name, not the result".

Strings compare in alphabetical order. Predict, then check

      

    

  

  
Done whena to g play their own note, and h, Enter and Shift play nothing.

  
The letter is the pitch, built with last week's string joining. Strings compare alphabetically: "c" >= "a" is true, "h" <= "g" is false. The surprise: "Enter" >= "a" is false, because every capital letter sorts before every small letter. That's why Enter happens not to play even without the length check; .length === 1 says what we mean (one character) instead of relying on that accident.
