A3: Functional Prototype

One person. One instrument. The pointer.

You keep Tone.js and the code structure from A1. What's new is the input: a mouse, a trackpad, a finger or a pen.

10:45. A1 was a group instrument played with the keyboard. A3 is an individual instrument played with the pointer. A key press happens or it doesn't. The pointer gives you a stream of positions, all the time, and how it moves (fast, slow, round and round, back and forth) is information your program can use.
A3: Functional Prototype · The brief

What A3 asks for

01The pointer shapes the sound. Pointer events, and the pointer's position and movement keep changing the sound: pitch, volume, filter, tempo.
02One more layer. Keys that trigger or switch the sound, or shapes on the page that move with the pointer's movement.
03Data processed over time. Speed, direction, distance travelled, where it has been. Not one reading.
04Required in the code: an object or an array, a loop, a const, an event handler. Settings and state; setup, update and use.
05Only JavaScript and Tone.js. No other libraries, no CSS transitions or animations. Runs without errors.
The brief in five rows. Stress 03: it's the one people miss. 02: no visuals are required; if you take the keyboard path, a plain page that makes sound is a complete submission. 05: "runs without errors" means locally and on the github.io page, so check the console on the live page before you hand in.

A3: Functional Prototype · Over time

One reading, or over time?

"Pointer x sets the pitch" isn't enough for A3. Sort each idea: does it read the pointer once, or need data from many events?

Give them a minute on their own laptops, then go through it on the projector. The test: could you answer it from one pointer event alone? Position: yes, so it's one reading. Speed needs this position and the one before, plus the time between them. Direction needs two positions. Distance travelled adds up every move. Shaking needs a history of directions. Hovering on the shape is one event. The last row is the interesting one: hovering is fine as a starting point (it's step 2 today), but on its own it doesn't meet criterion 3.

Guided build with shape.js · The file

What's in shape.js

shape.js makes a box on the page and gives you an object to control it with. script.js already brings it in at the top.

script.js · top

            

            
A shape is an object. Its element is the real thing on the page: that's what you listen to.

          

          

            
WriteWhat it does

            
              
Util.createShape("pad")Makes a new shape

              
shape.setPosition(x, y)Place it: 0 to 1 across, 0 to 1 down

              
shape.setSize(w, h)Size in pixels; one number for a square

              
shape.setColour(h, s, l)Hue 0–360, then saturation and lightness in %

              
shape.setRoundedness(r)0 is square, 1 is round

              
shape.setRotation(deg)Turn it, in degrees

              
shape.elementThe element on the page

            
          

        

        
Open shape.js on the projector for a moment and scroll through it: they don't need to understand all of it (it uses a class, which we haven't covered), only what's in this table. The methods are the shape's own functions, called with a dot, like synth.triggerAttackRelease. They can be chained: shape.setSize(100).setRoundedness(1). The important line is the last one: shape.element is the HTML element. Events happen to elements, so listeners go on shape.element, not on shape.

Move onto the shape, off it, click it, hold, let go, and wiggle. Watch the counts. The first four are like keydown and keyup: one event per thing that happens. pointermove is different: dozens of events a second. That stream is where speed and direction come from, which is Friday. Ask: which would you use to start a note? To stop it? Try pressing on the shape, dragging off, and letting go outside: pointerup doesn't count, because it happened somewhere else. What went wrong?

        

          

            
You move onto the shape. It changes colour, but there's no sound and no error. Why?

            

            

          

          

            
You wrote triggerAttack on enter, but forgot the pointerleave listener. You move off. What happens?

            

            

          

        

        
Two bugs every year. Left: sound hasn't been allowed yet, because nobody has clicked. The colour changed, so the function ran; the code is fine. Right: the note plays forever. Nothing is wrong as far as JavaScript knows, so there's no error to read. That's the hardest kind of bug: the console is quiet. A console.log("leave") in the function you think is running tells you whether it is.
