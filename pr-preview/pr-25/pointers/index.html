Recap and motivation · A different kind of input

A key and a pointer

A key

You press it. It's either down or it isn't.

It speaks only at the instant you press or let go. Between presses, there's nothing to hear.

Like knocking on a door: separate knocks, silence in between.

A pointer

It is always somewhere, even when your hand is still.

When it moves, the interesting thing isn't one moment. It's the path it travels, and how fast.

Like drawing with a finger in the air: one line, never "between".

No code on this slide, and none yet. Ask first, before revealing anything: what's the difference between using a key and using a mouse? Collect a few answers. Then draw out the two things that make a pointer different in kind. One: position is always available, even when nobody is doing anything. You can ask "where is it?" at any time; you can't ask a key "where is it?". Two: movement is information. Not only where you stopped, but how you got there, and how fast. Keep it lived experience: hands, not events.

MIDI is the shared language electronic instruments and computers use for notes. It numbers the keys of a piano: 60 is middle C, and each step of 1 is the next key, black keys included. 12 steps make an octave: 48 is C3, 72 is C5.

Part 1: Pointer events and position · Together

          
Press, then drag to bend.

          
Written live: the press starts a note, the drag bends it, letting go stops it. Before we run it: press in the middle and drag left. Up or down? And from the far right edge, can you still bend up?

        

        
About five minutes, live-coded in your editor, listeners on window, no shapes. pointerdown: Tone.start(), dragging = true, remember startX = event.clientX, synth.triggerAttack("C4"). pointermove: if (!dragging) return; let bend = (event.clientX - startX) / window.innerWidth (normalise); bend = Math.max(-1, Math.min(1, bend)) (clamp to -1..1); synth.detune.value = bend * 1200 (interpolate: plus or minus one octave in cents). pointerup: dragging = false, triggerRelease(), detune back to 0. Predictions: dragging left bends down; from the far right edge you can't bend up, because there's no room left to move. Why this demo: the press decides when, the drag decides how much. And it quietly previews Part 2: the bend comes from how far you moved since pressing, not from where you are. It's relative, and its range is -1 to 1, not 0 to 1. ±1200 cents is exaggerated so the room can hear it; a real pitch-bend wheel is usually ±200. Device notes in passing: on a trackpad, dragging means press and hold (or three-finger drag): same code, different body. On touch, the page scrolls instead unless document.body.style.touchAction = "none". If the pointer leaves the window mid-drag, pointerup can be missed; event.target.setPointerCapture(event.pointerId) on pointerdown fixes it (optional). The reference sketch is in the Notion plan and the pointers/ folder.

Same shape as Monday's gaps: keep the previous position and time at the top (they have to survive between events, so State), and on each pointermove compare the new one with them. Distance over time is speed, in pixels per millisecond. Move slowly: speeds well under 1. Flick: several pixels per millisecond. Point at the history: raw speed is jumpy, even when your hand feels smooth. Two honest edge cases worth a sentence: the very first move compares against 0, 0 at time 0, so it's nonsense (tiny); and if two moves arrive in the same millisecond, the time is 0 and speed is Infinity. Clamping on the next slide catches both. Also: when you stop, no event arrives, so speed keeps its last value. Data only arrives with events.

Part 2: Movement as data · Easing

        

        
Bend the line before you use it

        

          

            

              
two curves

              

            

            
Which one makes slow drifts nearly silent, and only fast swipes bright?

            

            

          

          

            
            
straightease-inease-out

          

        

        
Raw normalised speed feels twitchy: every small move makes it brighter. Easing is the third pipeline tool: it bends the 0 to 1 line before you interpolate. Trace one value by hand together first: t = 0.5. Ease-in: 0.5 * 0.5 = 0.25, below the straight line. Ease-out: 1 - 0.5 * 0.5 = 0.75, above it. So ease-in keeps small values small (slow drifts stay quiet) and only lets big values through. Ease-out does the opposite: even a small move jumps up. Both still go from 0 to 1, so the range doesn't change, only the shape. Then predict, and hear it on the next slide.
