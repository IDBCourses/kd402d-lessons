i grows by one each pass, so each start is pushed 0.4 seconds later than the one before. The last note has i = 3: 3 * 0.4 = 1.2 seconds. 1.6 is the common wrong answer: four notes, but three gaps, and the first note starts at 0. That's an off-by-one too. The console shows 1.2000000000000002: computers store most decimals a tiny bit off; you can't hear it. 12c is the morning's heads-up made into an exercise: a plain i * 0.4 is a time on Tone's own clock, which started when sound started; a few seconds later those moments are past and nothing plays. Tone.now() + makes it "from now". The timeline appears once they've answered or pressed Play.

Loops over loops

  

    

      

        
P1tune and lengths share an index: play tune[i] for lengths[i] seconds, with a running start time: start = start + lengths[i];

        
P2A loop inside a loop: the outer one counts repeats (r), the inner one walks the notes (i). Note number r * 4 + i starts at that number times 0.3. Then each repeat an octave up.

        
P3The fourth value is strength, 0 to 1: 0.5 + Math.random() * 0.5, with the first note always 1.

        
P4Optional: filter and map, loops with the bookkeeping done for you. Write the same thing as a for loop with push.

      

    

    

      
P2: every pass of the inner loop, for 3 repeats

      

      

    

  

  
Done whenthe tune plays with its own lengths, the melody repeats an octave higher each time, and every note sounds a little different.

  
P1: two arrays of the same length, joined by one index; the running start time is block 3's accumulator pattern, used for time. Warn if the lengths differ: a missing length gives no error, just a wrong note. P3: small, tasteful variation, not generative composition. P4 is a preview, not course material yet.
