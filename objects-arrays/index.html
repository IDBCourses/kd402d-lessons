Act it out: a line of notes

        

        
Count from zero, out loud, down the line. Then try each
          move and call out everyone's new number.

        

          
The front · position 0
            
unshift · someone joins at the front

            
shift · the first person leaves

            
Everyone else moves along one place, and gets a new number.

          

          
The end · the last position
            
push · someone joins at the end

            
pop · the last person leaves

            
Nobody else moves. Their numbers stay the same.

          

        

        
10:35. Before any syntax. Five volunteers stand in a line at the front, each holding a note on
          a sheet of paper (C4, E4, G4…). They are the array; their place in the line is their index. Count from zero,
          out loud, down the line: "zero, one, two…". Then act out the operations on real bodies: push: someone new
          joins the right-hand end. pop: the right-hand person leaves. unshift: someone joins the left-hand end, and
          everyone's number goes up by one. shift: the left-hand person leaves, everyone shuffles down. After each move
          the room calls out each person's new number. The shuffle is the point: adding or removing at the front moves
          everyone else; at the end nobody else moves. Ask: if the line was 1000 people long, which end would you rather
          work at? This slide names the four moves and which end each works on, so the picture and the words land
          together.

Changing a property uses the same reach as reading it, with = on the right. Run tone.note =

Objects · Bracket notation

        

        
Same reach, different syntax

        

          

            

              
today

              

            

            
Both give back "C4". With brackets, the label is a string,
              in quotes.

          

          

            

              
later: when only the program knows the label

              

            

            
When the label is in a variable, only brackets work. The dot looks for a
              label literally called part.

          

        

        
Use the dot when you know the label as you write. Keep the brackets in
          mind for later.

        
Keep it light: introduce brackets as the same reach in a different syntax, and move on. Why it
          earns its place: later, when the label isn't known until the program runs (which key was pressed, which
          setting the player picked), dot notation can't do it and brackets are the only way. Seeing it now means it
          won't come out of nowhere then. Arrays use the same brackets with a number: notes[0]. That's not a
          coincidence.
