Tie it back to Thursday's bug hunt: the octave arrived as text, "4" + 1 gave "41". == converts the kind of value before comparing (type coercion), so "4" == 4 is true: it hides that the octave is text, which is exactly the thing that broke the note. === compares value and kind, so it tells the truth. We default to ===, and turn text into a number on purpose with Number(). The last row: one equals sign isn't a question at all; it puts a value in the box. That one causes the most bugs in block 2, inside if.

The decision students made by hand in exercise 1c, now made by the code. if (isMuted) is enough: isMuted is already true or false, so === true asks the same thing twice. One block runs, never both, never neither. 5c: "false" in quotation marks is text, and in an if any text with something in it counts as yes, so the muted block runs and there's silence. That's the reason booleans have no quotation marks. Don't go deeper into truthiness today; "text with something in it counts as yes" is enough. Common snag: if (isMuted = true) with one equals sign: it puts true in the box and the answer is always yes.

Three branches, one chosen each run. JavaScript asks from the top and runs the first block whose answer is true; the rest are skipped, not even asked. That's why the else if doesn't need bpm >= 80 && bpm < 120: if JavaScript gets there, the first answer was already false. The edges: 80 is not less than 80, so middle (C4); 120 is not less than 120, so the else (C5). Drag the tempo on the right to 80 and 120 to check.

The plain-language and, or, not from the morning, with their symbols. ! flips: !isMuted is true when isMuted is false. && needs both sides true; || needs at least one. The two ifs are separate questions, so both, one or neither can play. Common mistake: duration === "8n" || "16n". It reads like English but each side of || has to be a whole comparison. The || key is usually Shift + backslash; on Swedish Mac keyboards Option + 7. Ask: isMuted = true, which still plays? (The high G: the second if doesn't care about isMuted.)

Making the decision visible is how you find bugs in decisions.
