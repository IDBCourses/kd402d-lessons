Part 1 · A common mistake

  
One, two or three equals signs

  

  
In this course: always === and !==.

  
The == vs === pitfall. == converts the types first (yesterday's type coercion), so 24 == "24" is true. === compares value and type, so it's false. Text from an input field is always a string, so == hides real bugs. And a single = isn't a question at all: it puts a value in the box. That one will cause the most bugs this afternoon, inside if. Open the workspace (W) and try them in the console if there's time.

Part 2: Conditionals and logical operators · 11:15

  
if acts on the answer

  

    

      
If the onion is peeled, chop it. Otherwise, peel it first.

      
( )The question goes in round brackets. Its answer is a boolean.

      
{ }Each block of work goes in curly brackets.

      
elseWhat to do when the answer is false. Optional.

      

    

    

      
onion.jsbright lines run

Pick up the handoff. We've been making booleans; now we use one to choose what happens next. Read it aloud in plain language first: if the onion is peeled, chop it, else peel it first. Toggle the value: JavaScript asks the question in the brackets, runs one block, skips the other. Never both, never neither. if (isPeeled) is enough: no need to write isPeeled === true, the value is already a yes/no. Common mistakes this afternoon: a semicolon after the brackets, if (isPeeled); { … }, which ends the if right there; and a missing closing curly bracket.
