Conceptual objective 3: the same kind of value plays different roles. 440 is a frequency (doubling it makes sense: an octave up). 4 in octave is a position on the keyboard (doubling it doesn't mean "twice as high"). 90 in bpm is a speed. All numbers; the meaning lives in how we use them and what we name them, like the onion's count, step number and rating this morning. Times 1.5 gives a fifth, the most consonant interval after the octave: a little music theory in arithmetic.

A way to fix it
Number(typedOctave) gives back the number 4 from the text "4". Do the arithmetic on that: "C" + (Number(typedOctave) + 1). And typedOctave itself? Still "4".

    

  

  
Done whennoteUp logs C5 and you can say why it was C41.

  
Type coercion, the one the morning set up with "5" + 3 vs "5" - 3. Plus with a string glues: "4" + 1 is "41", so the note is C41, 41 octaves up and far beyond hearing (Tone.js either plays nothing you can hear or stops with an error). Minus only works on numbers, so JavaScript quietly turns "4" into 4 and gives 3: it worked by luck. Number() is new: it's a function that takes text and gives back a number, so it's also a transformation that leaves typedOctave untouched. Brief the TAs on this one. Logging the note before playing it (exercise 5) is how you'd find this bug in real code.

Read Template literals (javascript.info) · Math.random (MDN)

    

  

  
Done whenPlay the piece gives a different melody every time, and the console logs each note.

  
Template literals: backticks, and ${…} drops a value into the text. `${pitch}${randomOctave}` is the same as pitch + randomOctave, and `Playing ${note}` is "Playing " + note. Math.random() gives a number from 0 up to (not including) 1; times 5, rounded down, gives 0 to 4: a position in "CDEGA". scale.slice(index, index + 1) takes one letter: slice gives back the part of a string from the first position up to, not including, the second, counting from 0. It wasn't in the lecture, so point it out. A pentatonic scale has no notes that clash, so any order sounds fine. The Hear one button plays sixteen notes from this exact code.

Variables steering a process again, now the sound itself. Filter: lets through frequencies below cutoff (lower = darker). FeedbackDelay: echoes; feedback 0 to 1 is how much of each echo comes back (near 1 it never stops). Reverb: decay in seconds. chain connects them in order and ends at the speakers. Common snag: leaving .toDestination() on lead as well, so you hear the dry and wet sound together.
