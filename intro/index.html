Welcome and course overview · How we learn

Act it out first. Then write it.

Some days you'll be part of the program: one person follows a step, another passes along the data, and the room watches what happens. Then we write the same thing in code.

How the course teaches: physical, out-loud enactment alongside careful basics (syntax, debugging, planning before typing). Why: programs are processes, and it's easier to understand a process you've been inside. It also trains you to explain what code does out loud, which is exactly what the oral exam asks. The workshop at 10:15 is the first taste of this.

02 · Introduction to programming and JavaScript · 09:30

A program is instructions a machine can follow.

Every step spelled out, in order, with nothing left to guess. The machine does exactly what you wrote, not what you meant.

The one idea for this part. People fill gaps in instructions without noticing; a computer never does. Most of learning to program is learning how much you normally leave out. Next slide makes that concrete.

Introduction to programming · Precision

Make a cup of tea

Clear enough for a person. Click each step to hear what a machine would ask.

Ask the room first: which step would a robot get wrong? Then click through. The point: every step hides questions a person answers without thinking. A program has to answer all of them. In the workshop at 10:15 you'll break a task like this into smaller and smaller steps with your bodies. (Tomorrow's Functions lecture comes back to this same recipe.)
Introduction to programming · Why designers code

Why interaction designers program

PrototypeTry an interaction for real: does it feel right when someone actually uses it? A picture can't tell you that.
ExploreCode is a material you can sketch with: change a number and see what happens.
BuildThe things you design (apps, installations, sensors, games) are made of code.
CollaborateTalk with developers in their terms, and know what's easy, hard or impossible.
Why this course is in an Interaction Design programme. You're not being trained as software engineers; you're learning to use code as a design material. Ask: has anyone built something with code before? Show one or two examples of past student prototypes if you have them.

Introduction to programming · The web page

Three layers of a web page

a plant's web pageHTML only

Fern

Last watered: 3 days ago

Same page, three layers. HTML says what's there: a heading, a sentence, a button. CSS says how it looks. JavaScript says what it does. Press the button in each state: with HTML only and with CSS, nothing happens, because nothing has been told to happen. Only JavaScript gives it behaviour. This course is about the JavaScript layer; you'll write a little HTML and CSS along the way. No code shown today on purpose.
Introduction to programming · Our language

JavaScript: the language of the browser.

Every web browser already runs it, so there's nothing extra to install, and everything you make can be opened with a link.

Why JavaScript for this course: it runs everywhere, it's what makes web pages interactive, and the ideas (functions, data, conditionals, loops) carry over to every other language you'll meet: Python, Processing, Arduino. It also has its quirks; we'll meet them as they come up.
